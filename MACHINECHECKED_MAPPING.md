# Navier–Stokes paper ↔ Lean: the audit's mapping

Each numbered statement of *Finite time blowup for Navier–Stokes* ([PDF](https://cdn.openai.com/pdf/32d9f210-8b73-45e0-91bc-82a30aef8a9a/navier-stokes.pdf), 166 pages, 8 September 2026) with the declarations of this repository at commit `f9e8bc5b38b6e212696e8a30e3e91517af887bbd` that state its clauses. The mapping is the auditor's reading of the paper and the Lean sources. What Lean establishes about each declaration is the audit's (`machinechecked check`); whether a declaration states the paper's claim is a reviewer's judgement, recorded on the Review page.

| Coverage | Meaning |
|---|---|
| Full | the declarations together state every clause, up to harmless reformulation |
| Composed | every clause follows, but only by combining the declarations through reasoning no Lean statement records (the auditor's argument) |
| Partial | they state some clauses; the note names those with no counterpart |
| Changed | a clause is stated with stronger hypotheses, a weaker conclusion, another bound or another setting; the note says how |
| Related | a comparable result, with no established implication |
| Notation | a convention or notation; the note says how the Lean expresses it |

- *Linked*: the audit links the statement to these declarations; notation is listed but not linked. Each reading has a confidence, shown with its note.
- *Reading*: the first mapping, or a second review's proposal checked declaration by declaration against the Lean statements (where they disagreed, the checked reading is recorded).
- *Imported*: whether each declaration's module is in the import closure of `NavierStokes.ComparatorSolution`. This is a build plan, not a dependency trace: it does not say that the headline proof uses the declaration.
- Statement numbers cited in the Lean docstrings follow an earlier version of the paper; every mapping was made by content.
